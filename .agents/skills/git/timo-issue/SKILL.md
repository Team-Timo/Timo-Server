# Timo 이슈와 브랜치

## 트리거와 실행 범위

- **"이슈 만들어줘"**: 기존 이슈를 먼저 확인하고 필요할 때만 생성한다. 브랜치는 자동 생성하지 않는다.
- **"이슈 확인해줘"**: 연결된 이슈의 제목·상태·URL만 확인한다. 이슈나 브랜치를 생성하지 않는다.
- **"브랜치 만들어줘", "브랜치로 checkout해줘"**: 확인된 기존 이슈에 연결된 브랜치 생성·checkout만 한다. 이슈를 자동 생성하지 않는다.
- **"새 작업 준비해줘", "이슈와 브랜치 준비해줘"**: 이슈 확인·필요 시 생성 후 연결 브랜치 생성·checkout까지 한다. 구현·커밋·푸시·PR로 이어가지 않는다.
- 위 명령이 없는 구현·커밋 요청에서는 이 스킬로 GitHub 이슈나 브랜치를 만들지 않는다.

1. [팀 규칙](../../../../docs/conventions/git-convention.md)의 이슈·브랜치 항목과 `git status --short --branch`를 확인한다. 요청·브랜치·열린 이슈를 대조해 같은 작업의 이슈가 있는지 먼저 찾는다. 번호가 있으면 실제 제목과 상태를 확인하고 재사용한다.
2. 이슈 생성 명령이 있고 새 이슈가 필요한 경우 기능은 기존 feature 템플릿, 버그는 bug 템플릿을 사용한다. 제목은 `[type] 한국어 요약`; 본문에는 문제/목적, 작업 범위, 완료를 판단할 Todo를 적는다. 실제 저장소의 담당자와 라벨을 확인하고, 자동 라벨이 붙는 유형은 중복 지정하지 않는다.
3. 이슈를 만들 때는 GitHub 도구 또는 인증된 CLI로 **한 번** 생성하고 URL·번호를 확인한다. 응답이 불명확하면 이슈 목록을 먼저 조회한다. 인증이나 권한이 없으면 이슈 초안을 보고하고 생성을 완료한 것처럼 말하지 않는다.
4. 브랜치 명령이 있으면 이슈의 Development에 연결된 브랜치가 있는지 먼저 확인한다. 새 브랜치가 필요하고 작업 트리가 안전하면 작업 유형 라벨의 영문 유형을 접두어로 사용해 `<라벨>/#<번호>-<짧은-영문-내용>`을 정한다. 자동 라벨이 아직 적용되지 않았으면 이슈 제목의 `[type]`을 확인한다. 내용은 핵심 키워드 1~4개, 30자 이내로 하고 이슈 제목 전체를 복사하지 않는다.
5. 브랜치 명령이라면 연결된 브랜치가 이미 있을 때 새로 만들지 말고 그 브랜치를 로컬에서 checkout한다. 없다면 `develop`을 기준으로 해당 이슈에서 생성하고 checkout한다. CLI 사용 시 `gh issue develop <번호> --base develop --name '<브랜치명>' --checkout`을 사용한다. 전환 후 `git branch --show-current`로 확인한다. 기존 작업 브랜치와 미커밋 변경은 임의로 옮기거나 덮어쓰지 않는다. 추가 `git push`는 하지 않는다.
6. 이번 명령에서 확인·생성한 이슈 URL과, 브랜치 명령이 있었다면 현재 checkout한 브랜치명을 보고하고 멈춘다.
