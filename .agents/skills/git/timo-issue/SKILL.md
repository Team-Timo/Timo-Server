# Timo 이슈와 브랜치

1. [팀 규칙](../../../../docs/rules.md)의 이슈·브랜치 항목과 현재 `git status --short --branch`를 확인한다.
2. 현재 브랜치명이나 요청에 `#번호`가 있으면 GitHub에서 그 이슈를 먼저 확인한다. 존재하면 재사용하며 새 이슈를 만들지 않는다.
3. 새 이슈가 필요하면 작업 유형을 정하고 저장소의 `.github/ISSUE_TEMPLATE/` 형식으로 목적과 확인 가능한 Todo를 작성한다. 제목은 `[type] 한국어 요약`, 담당자는 가능한 경우 현재 사용자, 라벨은 저장소의 실제 라벨을 기준으로 한다.
4. GitHub 도구 또는 인증된 `gh issue create`로 한 번만 생성하고 반환된 이슈 번호와 URL을 확인한다. 생성 결과가 불명확하면 조회한 뒤 재시도한다.
5. 브랜치가 필요한 새 작업에서만 `origin/develop`을 기준으로 `<type>/#<번호>-<english-summary>`를 만든다. 현재 작업 브랜치나 미커밋 변경을 덮어쓰지 않는다.
6. 이슈와 브랜치의 최종 URL·이름을 사용자에게 알린다. 인증이나 권한이 없으면 작성한 이슈 내용을 보여주고 중단 지점을 설명한다.
