# Timo PR 제출

1. [팀 규칙](../../../../docs/rules.md)의 PR 항목과 `.github/PULL_REQUEST_TEMPLATE`을 확인한다. 현재 브랜치·이슈 번호·원격 저장소·변경 범위·커밋을 확인한다.
2. `develop`, `main`, `deploy`에서는 중단한다. 작업 브랜치의 미커밋 변경이 있다면 제출 범위를 분명히 하고, 함께 커밋을 요청받은 경우 `timo-commit` 절차를 먼저 따른다.
3. `git diff --check`와 변경 유형에 필요한 빌드·테스트 결과를 확인한다. 새 Java 변경이 검증되지 않았다면 검증한다. 실패를 성공으로 보고하지 않는다.
4. 현재 기능 브랜치를 `origin`에 푸시한다. 실패 시 원인을 확인하고, 원격 상태를 조회한 뒤 재시도 여부를 판단한다. 강제 푸시는 하지 않는다.
5. 같은 head 브랜치의 열린 PR을 조회한다. 있으면 그 PR을 갱신하고, 없으면 `develop` 대상 Draft PR을 만든다. 제목은 `[type] #번호 - 한국어 요약`이다.
6. PR 본문에는 실제 변경 내용과 검증 결과를 템플릿 형식으로 작성한다. 이슈 연결은 `closes #번호`를 사용한다. `gh`를 쓸 때는 본문을 임시 파일에 작성해 `--body-file`로 전달할 수 있다.
7. PR URL과 남은 검증·리뷰 사항을 보고한다. 리뷰 승인, 머지, `deploy` 배포는 이 절차에 포함하지 않는다. 서버 톡방 메시지는 명시적으로 요청받았을 때만 보낸다.
