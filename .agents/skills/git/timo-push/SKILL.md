# Timo 푸시

## 트리거와 단계 경계

- **"푸시해줘", "push 해줘", "푸시 금지를 해제하고 푸시해줘"**: 현재 작업 브랜치의 검증된 커밋만 원격에 푸시한다.
- 구현·커밋 승인·PR 요청만으로 푸시하지 않는다. 이전의 푸시 금지 지시가 남아 있으면 명확히 해제된 경우에만 진행한다.
- 푸시 후 PR을 자동 생성하거나 기존 PR의 제목·본문을 수정하지 않는다.

## 실행

1. [Git 규칙](../../../../docs/conventions/git-convention.md)을 확인하고 `git status --short --branch`, 현재 브랜치, upstream, 원격 상태를 읽는다. `develop`·`main`·`deploy`에서는 멈춘다. 이번 작업에 미커밋 변경이 남아 있으면 누락 가능성을 알리고 푸시하지 않는다.
2. 원격에 없는 커밋과 변경 파일을 확인한다. 비밀정보가 의심되면 값을 노출하지 않고 멈춘다. 해당 커밋의 검증 결과와 `git diff --check`를 확인하며, 검증이 실패했거나 실행되지 않았다면 상태를 보고하고 푸시하지 않는다.
3. 원격 브랜치가 앞서가거나 갈라졌으면 강제 푸시하지 않고 상태를 보고한다. 안전한 경우에만 현재 작업 브랜치를 일반 푸시한다. upstream이 없다면 현재 브랜치 이름으로 설정한다.
4. 원격 반영된 브랜치와 커밋을 확인해 보고하고 멈춘다. PR은 별도의 "PR 만들어줘" 요청을 기다린다.
